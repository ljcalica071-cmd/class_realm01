# CLASSREALM — PROJECT DOCUMENTATION CONTEXT

## 1. PROJECT IDENTITY

### System Name
**ClassRealm**

### Tagline
**One Realm for Every Learning Journey.**

### Approved System Title
**Integrated Senior High School Attendance, Activity and Requirement Tracking, Teacher Lesson Planning, and Learning Materials Management System**

### Development Context
This project is a proposed integrated academic management system for Senior High School classroom operations. The current client context is based on a Senior High School Mathematics teacher who handles Grade 11 students.

The original proposal began as three separate system concepts:
1. Senior High School Attendance Monitoring and Management System
2. Senior High School Activity and Requirement Tracking System
3. Teacher Lesson and Learning Materials Management System

These were later consolidated and expanded following panel recommendations into the approved integrated system title.

# 16. ADMIN ROLE BOUNDARIES

- View teacher accounts
- Edit teacher accounts

- Monitor teacher count

### Admin DOES NOT:

- Create academic years

- Perform item analysis
- Set grading percentages
- Manage grades
- Manage performance analytics
- Manage lesson plans

# ClassRealm: Project Documentation & Checklist

## Project Overview
- **App name**: ClassRealm
- **Title**: Integrated Senior High School Attendance, Activity and Requirement Tracking, Teacher Lesson Planning, and Learning Materials Management System.
- **Tagline**: "One Realm for Every Learning Journey."
- **Goal**: Highly functional frontend-first prototype. Demonstrable CRUD and workflows without backend.

## Architecture Guidelines
- **Feature-based structure**: `lib/features/`, `lib/core/`, `lib/models/`, `lib/widgets/`, `lib/data/` (mock).
- **Responsive-First**: Web-first (Admin/Teacher), Mobile-first (Student/Parent).
- **Offline-First Simulation**: Every data-entry feature must handle local state, sync status, and error simulation.
